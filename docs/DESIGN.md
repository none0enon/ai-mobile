## 0. 一页纸总结

| 决定 | 内容 | 为什么 |
|---|---|---|
| 一套前端三个端 | Vue 3 + Vite + TypeScript。安卓打成 APK（WebView 壳，从 math-reader 演进），iPhone 和电脑用 PWA | 一份代码；APK 补齐推送、闹钟、后台播放、计步 |
| 本地优先 | 界面只读写本机 IndexedDB（Dexie），同步在后台 | 秒开、离线能看、Worker 挂了也能聊 |
| 实时对话直连 | 手机直接请求你自己的 API / 中转（同 math-reader） | 延迟最低；不经过第三方 |
| 自己的云端中枢 | Cloudflare Worker + D1 + R2，负责同步、主动消息、推送、少量代理 | "App 关着也能收到她的消息"必须有常驻的云端 |
| 记录级增量同步 | 服务器分配递增序号 `seq`，按记录拉取 / 推送，删除用墓碑 | 比 math-reader 的快照合并简单；不依赖设备时钟 |
| 多智能体 | 主对话、陪伴 · 快速、节律、番外、总结/记忆、向量化、检索、生图提示词、生图、主动消息、视觉、TTS、STT，各自选连接和模型，可设备用连接；文本功能可以"跟随"主对话或「陪伴 · 快速」 | 便宜的活交给便宜的模型；失败自动降级 |
| 向量检索在本机 | 向量（float16）随记忆同步，手机上暴力计算余弦；向量化 API 由你自选 | 不受 Cloudflare 免费额度限制，离线可用 |
| 控制标签 | 回复里夹带 `[expr:smile]` `[cg:…]` `[music:…]` `[call]` `[choice:…]` 等，流式剥离 | 中转对 function calling 支持参差；标签不影响流式正文 |
| 主动消息"先排期再触发" | 每天生成 Touchpoint，Cron 每 5 分钟触发，内容在触发时才写 | 可预测、可幂等、安卓可设精确闹钟 |
| 兼容 SillyTavern | 角色卡 V1/V2/V3、世界书、Chat Completion 预设（含正则脚本）、聊天 .jsonl 能导入也能导出；消息里的 HTML 和前端卡按白名单 / 沙盒渲染 | 已有的卡、预设和正则直接用，随时能带走 |
| 不写死任何预设 | 提示词、规则、作息、衣柜、台词、题库、演示角色都是数据。内置的放成文件，第一次打开时像导入一样放进库里，之后能改、能删、能恢复（§5.5） | 什么都能改；加一个文件就多一条 |
| 角色按唯一 id | 导入角色卡时生成唯一 id。她的世界、作息、衣柜、外观、图库都挂在这个 id 上，预设是大家共用的 | 同一个预设给不同角色用，画出来是各自的样子 |
| 消息按人分 + 各自的世界 | 一个角色只有一条聊天。每个角色有自己的虚拟小世界，你在真实世界（Google 地图）；去她的世界找她，或带她出门，都只在这条聊天里记一段"来到… / 离开…" | 像和真人聊天：换个场景不会多出一条会话；她有自己的生活，你出门时也能带上她 |
| 国内网络 | Worker 绑自定义域名；不依赖谷歌服务（不用 FCM、不用 Google Fonts） | `*.workers.dev` 常被屏蔽 |

## 1. 产品定位

一个"更像真人"的 AI 陪伴：
- 继承 SillyTavern 的可定制性（角色卡、世界书、预设）；
- 加上真人恋人会做的事：主动来找你、记得你说过的事、知道现在几点下不下雨、陪你吃饭学习睡觉、打电话、一起听歌、约会。

**不做**（至少 M6 之前）：群聊、文本补全（text completion）后端、多用户、上架应用商店。

## 3. 总体架构

```
┌───────────────── 客户端（同一份 Vue 代码）─────────────────┐
│ 安卓 APK（WebView 壳 + 原生桥）│ iPhone 主屏 PWA │ 电脑浏览器 PWA │
│ 界面：消息 / 一起 / 回忆 / 我的 + 场景 + 通话 + 设置              │
│ 本地库 Dexie：全部记录 + 向量 + 素材缓存；同步发件箱               │
│ 直连：主对话、视觉、生图提示词、TTS/STT、Embedding（你的 API）     │
└──────┬─────────────────────────────────────┬────────────┘
       │ /v1/sync /v1/blob /v1/relay /v1/push    │ 直连 HTTPS
┌──────▼──────────── Cloudflare Worker（Hono）────────────┐   ┌───────────────┐
│ D1：records（所有可同步记录）、touchpoints、devices、secrets…  │──▶│ 你的 LLM / 中转  │
│ R2：立绘、CG、语音缓存、每日备份（按内容哈希）                    │   │ NovelAI / TTS   │
│ Cron：*/5 触发主动消息；每天 04:00 规划 + 整理记忆 + 写日记 + 备份 │   │ 网易云 / 天气     │
│ 推送：Web Push(VAPID) / webhook（Bark、ntfy、PushPlus、企业微信…）│   └───────────────┘
│ 代理：NovelAI（解 zip）、网易云（cookie 在 secret）、天气缓存、     │
│       不允许浏览器直连的服务（白名单转发）                          │
└──────────────────────────────────────────────────────┘
```

### 3.1 一轮对话
1. 你发消息 → 写本地库 → 进同步发件箱。
2. 组装提示词（见 §5）：预设块 + 角色卡 + 世界书扫描 + 记忆检索（本机向量）+ 【当前环境】+ 场景规则 + 聊天记录。
3. 按"智能体分配"选连接：直连或经 Worker 转发，流式请求。
   - 流式读取移植 math-reader 的 `readAIStream`（`docs/index.html` 20405–20526）：按响应体首字符判断 SSE / JSON，兼容"中转把流标成 JSON"。
4. 每次收到累积全文 → `parseControlTags(全文)` → 显示正文，立绘实时换表情。结束后执行其余标签（配图、歌曲卡、选项、来电）。
5. 回复写本地库并同步。未总结的消息累计到阈值后，在空闲时交给总结智能体。
6. "生成中"的状态只放内存，不进同步数据。生成期间暂停同步。每次 await 之后按 id 重新取对象。这三条都是 math-reader 回滚提交 8f24892 留下的教训。

### 3.2 主动消息
1. 每天 04:00（按你的时区），规划器按规则生成当天的 Touchpoint，`id = 日期:规则`。
2. Cron 每 5 分钟取出到点的 Touchpoint，过闸门：勿扰、上限、你 20 分钟内刚聊过、学习或睡觉中、连续两次没理会就退避。
3. 主动消息智能体用最新上下文写消息 → 写入 D1（`proactive: true`）→ 按推送通道依次尝试。
4. 客户端补齐：
   - 安卓壳到点的精确闹钟拉 `/v1/inbox`；
   - 任何一端打开 App 时都会同步。
   - 因为 id 固定，Worker 触发和打开 App 补发不会重复。

### 3.3 同步与大文件
- 记录：`GET /v1/sync/pull?since=seq`、`POST /v1/sync/push`（§12）。
- 大文件：先 `PUT /v1/blob/{sha256}`，记录里只存哈希。同一个文件只传一次，不需要两段提交。

## 4. 智能体与控制标签

### 4.1 分工

| 智能体 | 何时触发 | 产出 | 在哪运行 | 建议模型 |
|---|---|---|---|---|
| 主对话 | 每次发言 | 角色回复（含控制标签） | 本机 | 强模型（Claude / DeepSeek / Gemini，经中转） |
| 陪伴 · 快速 | 一起做事时：在场景里即时回应、批量写弹幕和批注、前情提要、台词池、海龟汤判定 | 短句、JSON（用这个场景的功能预设） | 本机 | 便宜、快的模型（Gemini Flash / Flash-Lite、Claude Haiku、DeepSeek flash）；没设置时跟随主对话 |
| 节律 | 导入角色时"建世界"；每天凌晨 4 点"排今天" | 她的世界（地点、身边的人、作息模板、三餐习惯、衣柜）；今天的作息、三餐、穿着（JSON） | Worker 或本机 | 默认跟随「陪伴 · 快速」 |
| 健康计划 | 打开"健康计划"、在"健身"里选"按照计划"时，这周 / 今天还没排；手动"重新排" | 这周每天练什么和三餐方向、要买的东西；今天的动作（复杂的写清楚怎么做）和三顿饭的做法（JSON，「健康」预设） | 本机 | 默认跟随主对话（要写得细） |
| 番外 | 你很久没来、夜间、手动"写一段她的番外" | 她在自己世界里的一小段故事 + 可能发给你的一句话（hook）+ 适合配图的一幕（cg），JSON | 本机或 Worker | 便宜模型，温度高一点 |
| 总结 / 记忆 | 未总结消息攒够 x 条（消息设置，1–100）、手动整理、补整理 | 梗概（进时间线）+ 故事片段（带标签）+ 记忆条目（带来源行）+ 关系变化（JSON） | 本机 | 便宜快的模型 |
| 记忆整理 | 每天凌晨 4 点（用户时区）、记忆本"立即整理"、没连云端时打开 App 补跑 | 一串修改：合并重复、合并时间线、改时态、画像卡逐行增删改 | Worker / 本机 | 便宜快的模型，和总结分开配置 |
| 向量化 | 新记忆和片段写入、查询、换模型重算 | float16 向量 | 本机 | 任意 OpenAI 兼容 `/embeddings`（bge-m3 等） |
| 检索 | 每次她回复完成后（给下一轮用） | 分路取到的记忆和片段 | 本机 | — |
| 生图提示词 | `[cg:]`、手动"生成配图"、各场景的时刻（§10.3）、主动自拍 | NovelAI tags（JSON） | 本机或 Worker | 默认跟随「陪伴 · 快速」 |
| 生图 | 上一步之后 | 图片 → R2 → 相册 | Worker（代理 NovelAI） | NovelAI V4.5 |
| 主动消息 | Touchpoint 到点 | 1～2 条消息，可带 `[call]` `[cg]` | Worker | 便宜模型，或和主对话同款 |
| 视觉 | 饭照、运动截图 | 点评 / 结构化数据 | 本机 | 多模态模型 |
| TTS / STT | 语音消息、通话 | 声音 / 文字 | 本机（必要时经 Worker） | CosyVoice / SenseVoice 等 |

每个智能体在"API 与智能体"页单独选：连接 + 模型 + 参数 + 备用连接 + 在哪运行（本机 / Worker / 自动）+ 每日 token 上限。

- **跟随**（第二阶段）：主对话以外的文本功能，可以跟随「主对话」或「陪伴 · 快速」，不用自己的 API。
  - 生图提示词和节律默认跟随「陪伴 · 快速」；
  - 「陪伴 · 快速」没设置时跟随主对话，它自己也只能跟随主对话，不会绕成圈；
  - 以前的"跟随主对话"开关（`AgentRoute.sameAsMain`）自动迁移。
- **一起做事时谁来说话**：
  - 场景里的话用「陪伴 · 快速」，但提示词仍然是这个场景的功能预设，所以她说话还是她的样子。觉得便宜模型不像她了，可以一键改回跟随主对话；
  - 聊天页里的对话，以及场景结束后她在聊天里说的收尾，用主对话和这个角色的对话预设。

### 4.2 总结 / 记忆智能体的输出

聊天记录每行带编号和时间（`#12 [11-02 周六 22:10] 名字: 内容`），给模型看的已有记忆是和这批聊天最相关的约 30 条（向量 → 字面 → 最近的）加置顶和到期的。

```json
{
  "summary": "这一段的梗概（第三人称，100–200 字，写清日期）",
  "slices": [
    { "title": "面试前夜", "text": "他说 11 月 3 日下午两点面试，她给他打气", "from": 3, "to": 9, "mood": ["温馨"], "special": ["考试"], "important": false }
  ],
  "memories": [
    {
      "type": "fact|preference|event|promise|followup|emotion|relationship",
      "content": "11 月 3 日下午两点有实习面试",
      "importance": 8,
      "dueAt": "2026-11-03T16:30:00+08:00",
      "supersedes": ["mem_xxx"],
      "lines": [3, 4],
      "entities": ["面试"]
    }
  ],
  "relationship": { "affectionDelta": 1, "mood": "有点想你", "nicknames": { "user": "笨蛋" } }
}
```

- 只从"已定稿"的消息里抽：跳过最后 4 条，跳过没被选中的 swipe。
- 程序按行号记下精确的来源消息和发生时间；一条只写一件事、写名字、写具体日期写在预设规则里。
- 写完把新记忆和片段向量化；和已有记忆相似度 ≥ 0.9 的标"可能重复"（dupOf），留给整理；和忘掉过的相似度 ≥ 0.92 的直接丢掉。
- 好感变化每次最多 ±3。

### 4.3 生图提示词智能体的输出

```json
{ "caption": "雨天的图书馆", "tags": "1girl, …, library, rainy window, warm desk lamp", "negative": "lowres, …", "size": "portrait" }
```

- 外观基础 tags 来自角色卡的"外观 tags"，服装 tags 来自当前场景。

### 4.4 番外智能体的输出

```json
{ "title": "借伞的人", "story": "第三人称的小故事（150–250 字）", "time": "傍晚", "place": "图书馆门口", "mood": "有点好笑", "people": ["学弟"], "hook": "今天把伞借出去了…", "cg": "傍晚图书馆屋檐下，她抱着书看雨" }
```

- 输入：角色卡、她的世界（作息、手头的事、三餐、身边的人）、此刻在哪、她记得的关于你的事、最近的聊天、最近写过的番外标题（避免重复）。
- 你不出场，但她可以想到你、提起你们聊过的事；写一个小而具体的事件，不写流水账。
- `hook` 可以当作一条主动消息发给你；`cg` 交给配图流水线（§4.5）。以后番外写进她的"生活记录"，聊天时她能自然地提起。

### 4.5 AI 调用层（`packages/ai`）

前端和以后的 Worker 共用，只用 Web 标准接口（tsconfig 用 `WebWorker` 库）。说明见 `packages/ai/README.md`。

- **真调用还是演示**：智能体的主连接分配了、这台设备上有 Key（或连接不需要 Key）、协议能做这件事，才真的调用；否则界面继续用演示实现。"API 与智能体"页每个智能体写着"已接通"或"演示模型 · 原因"。
- **Key**：存在本机数据库单独的 `secrets` 表，不和连接、分配放在一起，永远不进同步数据。
- **备用连接**：语音只换同一种协议的备用（音色 id 只在同一家有效）；向量化只换同一个模型族的备用（不同模型的向量不能比较）。
- **思考的余量**：会思考的模型把思考的 token 也算在回复上限里（Gemini 的 maxOutputTokens、Claude 的 max_tokens、多数中转的 max_tokens）。预设里的"最长回复"是给正文的，短回复的功能（通话 160、戳一戳 100、哄睡 300……）会被思考吃光：回复是空的（MAX_TOKENS），或者只剩一个标题。所以发请求时在预设上限之外再留余量（`llm/reasoning.ts`）：
  - Gemini 原生：设了思考预算按预算留，设了思考等级按等级留（minimal 1024 / low 4096 / medium 8192 / high 16384），没设（默认动态思考）留 8192，预算为 0 不留；
  - Claude：自适应思考按强度留，默认就会思考的型号没设强度时留 8192；DeepSeek 官方：没设强度时（现在的模型默认思考）留 8192；
  - OpenAI 格式（中转）：名字看得出默认会思考的（Gemini 2.5 起、o 系列、GPT-5、DeepSeek R1、QwQ、Grok 3 mini / 4、GLM 4.5 起）留 8192；名字写明不思考的（-chat、-instruct、no-thinking）不留。
  - 要快的回复（通话、哄睡、看片时随口一句）在认得思考参数的原生接口上把推理强度设成 none（Gemini 预算 0 / 最低等级、DeepSeek 关思考、Claude 不开）；OpenAI 格式的中转不一定认这个参数，不发。你在 API 设置里自己设了推理强度时照你的。
- **设置在哪**："API 与智能体"页：连接（火山引擎填 APP ID；OpenAI 兼容的对话连接在"高级"里选消息整理、写额外 / 去掉的请求参数）、每个对话智能体的推理强度和要不要思考过程、生图智能体的生图风格、回复修剪规则。"语音"页：朗读哪些字、火山引擎的声音复刻。
- **配图**：`[cg:]` → 生图提示词智能体（JSON：caption / tags / negative / size，外观 tags 由程序放最前面）→ 生图智能体 → 本机素材库（`assets` 表，按 SHA-256 内容哈希，以后同一个哈希传 R2）→ 消息里的图片卡片。失败时卡片上写原因，可以重画；生图智能体没接通时也写原因，不用占位画冒充。
  - 两个入口：主对话回复里的 `[cg:画面描述]`（写法和时机写在程序填充的"场景规则 + 可用标签"块里，导入的 ST 预设也有）；聊天 ＋ → 生成配图（`components/chat/DrawSheet.vue`：选画什么——场景 / 全身像 / 脸部特写 / 只画背景——可写一句画面），直接走生图提示词智能体 → 生图智能体，不经过主对话。
  - "画什么"决定生图预设里发哪一块（块的触发条件），图片卡片记着 `mode`，重画时照原样再画。

| 标签 | 作用 |
|---|---|
| `[expr:smile]` | 切换立绘表情。只允许立绘套装里有图的表情，列表会写进提示词 |
| `[pose:sit]` `[outfit:pajama]` `[bg:cafe]` | 姿势 / 服装 / 背景 |
| `[cg:画面描述]` | 请求配图 |
| `[music:歌名-歌手]` | 分享歌曲（生成歌曲卡片，可"一起听"） |
| `[call]` | 想打电话（弹出来电横幅） |
| `[choice:A\|B\|C]` | 约会选项（显示成快捷回复） |
| `[poke:部位]` | 回戳你 |
| `<device>"VIBRATE": 40</device>` | 心跳里玩具的控制指令（尖括号、成对，可以跨行；写法见 §9.14） |

- **兼容写法**：全角 `【expr：smile】`、名字不区分大小写。不认识的方括号（例如"[笑]"）原样保留为正文。
- **`<device>`**：不管在哪个场景都从正文里拿掉（单独一行的连同换行），聊天里不显示、语音不念；只在心跳的白名单里（`allowedTags` 带 `device`）记下位置交给场景执行。流式时还没收完的 `<device>…`、结尾半截的 `<dev` 先藏起来。
- **两种解析**：
  - `parseControlTags(全文, 场景白名单)`：无状态，每次拿累积全文重新解析，配合 `readAIStream` 的 `onDelta(全文)`。返回每个标签在正文里的位置（剧场模式的打字机打到这里才换表情），结尾半截标签先隐藏（`pending`）。
  - `createTagStripper()`：给只提供增量的流用。
- **场景白名单**：不在当前场景白名单里的已知标签，照样从正文去掉，但不执行。
- **标签说明写在预设里**（第二阶段）：每个标签的写法和什么时候用，写在预设的"可用标签"块里。现在是由代码（`CONTROL_TAG_DOCS`、`services/prompt.ts` 的 `tagsLine`）拼进提示词的，要搬走（§5.5）。程序只按场景白名单决定执行哪些标签。

- **家务和健康**（程序填充块 `home`）：家务清单和今天做了没有、拖了几次、几天没做，以及健康目标、今天的健身和饮食计划、今天练了没有。块的触发条件除了生成类型和场景任务名，还认 `flags`：你人设里开着的系统（`LIFE_FLAGS`：housework、health），"她怎么反应"那两块只在开着时发。预设里没有这一块（以前导入的 ST 预设）时接在最后；预设里没有"她怎么反应"的块时，用自带预设文件里的接在今天的情况后面。云端主动消息用手机上传的那份（时间按半小时取整）。
- **场景任务**（第二阶段，程序填充）：一起做事时，程序只往这一块里填这一次的输入，例如一段字幕、一道汤和之前的问答、刚结束的番茄。它由主动消息的 quiet 机制扩展而来：预设里有这一块就填进去，没有就接在最后。做哪件事由块的触发条件决定（§5.5）。
- **排序原则**：稳定内容在前、易变内容按深度插进聊天记录末尾。这样能命中 DeepSeek / OpenAI 等的前缀缓存。
- **作者注**：按 ST 的 depth 规则插入。角色卡的 `extensions.depth_prompt` 同样按深度插入。
- **"查看提示词"页**（`/chat/:id/inspect`）：发送时拼好的提示词原样留在内存里，这里列出发出去的每一条消息、预设每一块（发没发、为什么）、世界书每一条（触发没有、为什么）、请求体。还没发过时按现在的聊天预览（不推进世界书的粘性 / 冷却）。
- **实现**：`packages/shared/src/st/assemble.ts`（按 ST 的 `populateChatCompletion`），App 的四块内容在 `apps/web/src/services/prompt.ts` 里填好传进去。和 ST 一致的细节：
  - 预设里关掉的块不发；关掉的主提示在 ST 里是一个空占位，同样不发；空内容的消息不发。
  - 聊天记录开头插 `new_chat_prompt`；示例对话每段前插 `new_example_chat_prompt`，每句是带 `example_user / example_assistant` 名字的系统消息。
  - 按深度插入的内容（预设的 in-chat 块、世界书 @深度、角色卡 `depth_prompt`、作者注位置的世界书）同深度同角色合成一条；`injection_order` 大的更靠后。
  - 角色卡的 `system_prompt` / `post_history_instructions` 覆盖主提示 / 后置指令，可用 `{{original}}`。
  - 预算 = 上下文 − 回复最长；聊天记录从最新往旧放，示例对话最后放。
  - 比 ST 多做的一点：示例对话也认全角冒号"名字："（ST 会把这种行丢掉）。

### 5.5 不写死任何预设：内置的东西都是文件（第二阶段）

- **规矩**：代码里只留三样东西：
  - 界面文字；
  - 协议：标签名、JSON 字段名、时刻名、任务名；
  - 算法：计时、拼装、检查。

  提示词、规则、输出格式、作息、三餐、衣柜、台词、题库、小世界、演示角色，一律是数据。
- **内置的东西都照预设文件的做法**（`stores/library.ts` 现在对 `src/presets/` 就是这么做的）：
  1. 一类东西放一个文件夹，一个文件是一条；往文件夹里加一个文件，就多一条；
  2. 第一次打开时（或 App 更新后多了文件），像导入一样放进本机的库，并记下哪些文件放进来过；
  3. 之后就和你自己导入的一样：能改、能删、能复制、能导出；删掉的不会再放回来；
  4. 记着来自哪个文件，可以"恢复成文件里的样子"。

### 5.6 正则、消息条数和 HTML（我的 → 消息设置）

- **正则随预设保存**（`packages/shared/src/st/regex.ts`，对应 ST 的 `extensions/regex/engine.js`）：预设编辑 → 正则中导入（ST 正则脚本单个或数组，或包含正则的 ST 预设、角色卡、App 预设文件）、新建、编辑、启用 / 停用、拖动排序（按列表顺序依次执行）。
  - 查找写成 `/正则/标志`；未写斜杠时整串作为正则、无标志，仅替换第一处（ST 的 `regexFromString`）。替换支持 `$1`、`$<name>`、`{{match}}`；捕获内容先移除 trimStrings，最后替换宏。
  - 作用范围：用户输入 / AI 输出（斜杠命令、世界信息、推理导入时保留、导出时写回，不执行）。

- **显示条数**（1–100）：聊天顶部按钮每次再展开同样条数，切换聊天后复原。
- **HTML 渲染**（默认开启）：消息中的 HTML 按白名单重建节点（`utils/html.ts`，未知标签只移除标签、保留文本，同 ST 的 DOMPurify）；正文换行转为 `<br>`，HTML 结构中的缩进和换行按网页规则合并。
  - 代码块中的完整 HTML 页面（含 `html>`、`<head>`、`<body>`，同酒馆助手的判断）在沙盒 iframe 中运行（`utils/frames.ts`，`allow-scripts` 不含 `allow-same-origin`，无法访问应用数据和 Key），仅渲染最近 N 条（0–50，默认 5），更早的和生成中的折叠为代码。
  - 页面头部注入桥接脚本：上报高度（vh 换算为固定像素，避免高度循环增长）；提供酒馆助手的 `getCurrentMessageId` / `getLastMessageId`（从 0 计数）和 `eventOn` / `eventOnce` / `eventEmit` / `eventRemoveListener`（转发给所有页面）。新消息、切换主题通过 postMessage 通知，不重新加载。

| 层 | 内容 | 存储 | 进提示词 |
|---|---|---|---|
| 短期 | 最近 N 条（按发送条数和 token 预算；可以只发还没总结的） | messages | 聊天记录 |

| 时间线 | 每次总结的梗概；同层满 4 段合并成上一层一段，各层还没合并的段覆盖全部历史（越早越粗） | summaries（level、mergedInto） | 过往摘要 |
| 事实记忆 | 类型、内容、重要度、发生时间、来源消息、涉及的人和物、向量、状态 | memories | 取到的才带 |
| 故事片段 | 按话题切的一段经过：标题、经过、起止消息、时间、标签（氛围 / 特殊日子或状态 / 重要）、向量 | slices | 取到的才带 |
| 待跟进 | 带 `dueAt` 的记忆，到期由主动消息去问，过期由整理改时态 | memories(type=followup) | 到期的每次都带 |

- 本机库（IndexedDB）四张表 memories / slices / summaries / profiles，按条写入；向量读库时解码进内存，字面索引（单字 + 两字，BM25）也建在内存里（`stores/memory.ts`）。
- 以前写在聊天上的摘要（`chat.summaries`）第一次打开时搬进时间线。
- 已经总结过的消息被改或删：相关片段标"要重新生成"（先不参与检索），相关记忆标"来源改过"（记忆本里提示复核）。

### 6.1 检索（本机，`packages/ai/src/agents/recall.ts`）
- **时机**：她每次回复完成后，用"这一轮你的话 + 她的回复"（各取前 300 字）在后台搜一次，结果按聊天存最近 3 份；你发下一条时直接用存好的，不等网络。纯寒暄沿用上一轮的结果。发送时只在本机用你这一轮的话按字面、按时间说法补最多 2 条。重新生成沿用那条回复原来用的结果。
- **两种搜法**：按意思（查询向量和记忆向量的余弦）和按字面（BM25，中文拆成单字和相邻两字，单字权重 0.3），两边名次用 RRF 合并：`Σ 1/(60 + 名次)`；涉及的人和物出现在这句话里时当作第三个排名的第一名。再乘重要度（0.8 + 0.2·重要度/10）和按类型的新近度（情绪半衰 14 天、事件 120 天、事实偏好关系不衰减）。
- **只按意思对上的**要过相似度下限（默认 0.3）并且离最相关的那条不超过 0.2；字面要对上不常见的两字词。
- **分路**（最多 8 条，约 900 token）：时间说法（范围里的 3 条，或"第一次 / 上次"取最早 / 最近的 1 条）→ 最相关 3 → 重要 1 → 今天的特殊日子（节日含农历、生日、纪念日、相识整百天）1 → 上下文提到的状态（生病、出差、考试……）1 → 回响。
- **回响**：带过的条目普通 2 轮、重要 3 轮，之后只要还在合并排名前 50 名就继续带，每轮消耗一次。
- 放进提示词时按发生时间排好、带日期；被带上的 `recallCount + 1`。"查看提示词 → 记忆"里列出每条的入选原因和分数。
- 向量化没接通或失败时只按字面搜。主动消息不搜，只带每次都带的和最重要的 30 条。

### 6.2 向量
- 每条记忆和片段存 `{ model, dims, data: float16 base64 }`。只比较和当前设置同一个模型族、同一维度的向量；换模型后"API 设置 → 重算全部向量"（记忆 + 片段）。
- 手机上暴力计算：4000 条 × 1024 维，一次检索约 7 ms（Node 实测）。
- 不用 Cloudflare Vectorize。

### 6.3 记忆整理（"记忆整理"的 API 和"整理 · 记忆"预设）
- **打包**（`services/consolidate.ts`）：可能重复的组（写入时的 dupOf 连成组）、时间线该合并的组、过期 6 小时以上的待跟进、画像卡和上次整理后新记下的事。
- **四件事各一次调用**（`packages/ai/src/agents/consolidate.ts`，预设里按任务类型发不同的块）：merge 合并重复（旧的标 superseded，不删）；rollup 合并时间线；tense 过期的事改时态（事情过去了改成 event，还值得再问留 followup）；profile 画像卡逐行增删改，不整张重写。很久没用到的小事（重要度 ≤ 3、没被想起过、120 天以上的事件 / 情绪）按规则归档。
- **在哪跑**：连了云端时每天凌晨 4 点（用户时区）在 Worker 上跑，结果写成修改记录，手机打开时拉取应用；没连云端时打开 App 后距上次超过 20 小时的角色在本机补跑；记忆本里也能"立即整理"。
- **冲突**：应用每一处修改前对照打包时的内容，你在手机上改过的跳过（合并的标记留着，下次再合并）。
- 总结、整理、补整理都不设每日上限。

### 6.4 记忆本（用户可控）
画像卡（可以加、改、删行）、搜索、按类型筛选、待复核 / 可能重复 / 以前的；改内容和重要度、置顶、"忘掉这件事"（留墓碑，之后的总结写出一样的事也不再记）、放回去、回到原话；立即整理、补整理聊天记录（一批一批，可以暂停）。

  - 她此刻在哪由她的作息决定（`Character.locationId`），她的头像标在她的世界里。
  - 第二阶段改成：
    - 世界是存在她 id 下的数据。演示角色的世界放在她的卡片文件里；导入的角色由「节律」的"建世界"生成（§5.4）；
    - 不再套写死的模板，也不借用别的角色的世界；
    - 底图按她的地点自动排布；
    - 她此刻在哪，先看她今天的节律。
- **你在真实世界**：用 Google 地图。
  - 内容：家、你此刻在哪、附近可以带她去的地方。
  - 附近的地方来自 Google Places（咖啡店、餐厅、公园、健身房、图书馆），种类决定能一起做什么。
  - 这些真实地点在运行时登记进同一个地点表（`registerPlaces`），聊天、场景、提示词都认得。

**三种"在一起"**：你的人和要做的事永远在真实世界（真的在学、真的在吃），她的生活在她的世界里，"一起"就是把两边接起来。

| 方式 | 你 | 她 | 像什么 | 默认用在 |
|---|---|---|---|---|
| 连线 `remote` | 在你那儿 | 在她世界里做这件事的地方 | 开着视频各做各的 | 学习、吃饭、运动、哄睡、听歌 |
| 去她那 `visit` | 人在你这儿，画面进她的世界 | 在她的世界 | 去她学校找她、坐她旁边 | 约会、戳戳乐 |
| 带她来 `bring` | 在真实世界的某个地方 | 在你身边（手机里） | 出门戴着耳机带上她 | 点了"我的世界"里的地点 |

- 场景页顶栏显示是哪种方式（"连线 · 你在家"），连线和去她那可以随时切换（`Chat.togetherMode`）。
- 聊天里的分隔条也按方式写：
  - 连线："和苏晚连线 · 陪伴学习 · 你在家，她在图书馆" …… "结束连线 · 学了 50 分钟"；
  - 去她那："和苏晚来到电影院 · 约会"；
  - 带她来："带苏晚去街角咖啡店 · 约会"。
- 怎么选由 App 建议：
  - 你在真实的图书馆、餐厅（打开 App 时定位到）→ 建议带她来；
  - 她按作息正好在图书馆、食堂 → 建议连线；
  - 你点她世界里的地点 → 连线（约会、戳戳乐是去她那）。

**她自己的生活**（`World.schedule`、`World.life`）：
- 每个角色有一张作息表，几点在哪、在做什么，和你用同一个时间，这样饭点、睡觉才对得上：
  - 苏晚：白天在图书馆写论文，傍晚去江边散步，晚上再回图书馆自习；
  - 江屿：六点晨跑，下午训练，晚上加练。
- 打开 App 时按作息算出她们此刻在哪（M3 起由 Worker 的 Cron 推进并同步）。
- 她也有自己的任务和三餐。连线自习时她在写"宋词里的雨"，饭搭子时她在吃食堂的麻辣烫，所以"一起"是双向的，她不是一直在等你。
- 她世界里的其他人（室友、同学、导师），在导入角色卡时一并生成（见 §5.4）。
- 第二阶段：作息、三餐、穿着都由下面的「节律」管，存在她的 id 下，不写在代码里。苏晚、江屿的这些数据放进她们的卡片文件。

**我们的足迹**：你在真实世界里和她们一起待过的地方，包括连线时你在哪、带她们去过哪。这些地点在"我的世界"地图上带一颗小心，下面列出最近一起做了什么。

**地图页**：上面一排切换"苏晚的世界 / 江屿的世界 / 我的世界"（`?world=`）。
- 在她的世界里：
  - 点地点 → 在那里能和她做什么 → 进入场景（默认连线：你在你那儿，她在这里）；
  - "一起做点什么"的大按钮 → 选她世界里的哪个地方；最后两格固定是"打电话"和紧挨着它的"共同的家"（§9.12）；
  - 点头像 → 去找她 / 发消息 / 打电话。
- 在我的世界里：
  - 点附近的地方 → 选带谁、做什么 → 她"来你这边"陪你（聊天里记"带苏晚去街角咖啡店 · 约会"）；
  - 这时她的世界里显示"她现在在你那边"，离开后她回到自己的世界。
- 从聊天的 ＋ 面板直接进场景时，去她世界里做这件事的默认地点（`defaultLocationFor`）。
- 没填 Google 地图 Key 时，我的世界显示示意图（同一套地图组件画几条街），附近地点用演示数据。

**Google 地图接入**（M3，**已实现**：`services/maps.ts`、`stores/realworld.ts`、`components/map/RealMap.vue`；Key 在"我的 → 地图、天气、音乐"）：
- 在"连接"里加一个 Google 地图连接，Key 只存本机，并在 Google Cloud 里按 App 包名 / 网址限制。
- 用到三个接口：
  - Geocoding：设置家时把地址换成坐标，只调一次，结果缓存；
  - Places API (New) 附近搜索：按种类找附近的地方，结果缓存一天；
  - Maps JavaScript API：画真地图，你和带出门的她标在上面。
- 定位先只做前台：打开 App 时取一次（网页定位；安卓壳里用系统定位），不做后台定位和地理围栏。
- 接口统一放在 `services/types.ts` 的 `MapsClient`，所以以后换高德等地图服务时，页面不用改。
- 实现上：附近搜索直接调 Places API (New) 的 REST 接口（`places:searchNearby`，`X-Goog-FieldMask` 只要名字、地址、坐标、类型名、Google 地图链接），按种类各搜一次（`includedTypes`，咖啡店 / 餐厅 1.5 km，公园 / 健身房 3 km，图书馆 5 km），每种留最近的 3 个；搜到过的地点存在本机（最多 200 个），足迹过几天也认得出名字。
- 健康计划另外用同一个接口搜附近能吃饭的地方和超市（`searchFood` / `searchGroceries`，`MapsClient.food` / `groceries`，见 §9.13），各缓存一天。
- 真地图用 `OverlayView` 的一层 DOM 画地点、你（定位的蓝点）、跟着你出门的她，不需要 Map ID；脚本加载失败或 `gm_authFailure`（Key 被拒）时退回示意图并写明原因。换 Key 要刷新页面（脚本只加载一次）。

**消息按人分**：一个角色只有一条聊天。场景不另开会话，而是这条聊天里的一段：
- 开始时插一条分隔（例如"和苏晚连线 · 陪伴学习"），结束时插一条（例如"结束连线 · 学了 50 分钟"）。用的是 `MessagePart` 的 `scene` 类型，记着方式 `mode` 和你在哪 `youAt`，在聊天里显示成分隔条。
- 进来后什么都没发生就离开：两条都撤掉，她也回到原来的地方，不留痕迹。
- 场景只在场景页上：离开场景页就是结束这件事，点她的那句话去聊天、打电话也一样。聊天页只是聊天：回复用这个角色的对话预设，不带场景规则；顶栏和剧场背景是她自己此刻在的地方。
- 上次在场景页里直接关了 App（没走到"离开"）的，下次打开 App 时那件事算结束。
- 会话上记着三件事：`togetherAt`（她那边在哪）、`togetherMode`（怎么在一起）、`currentScene`（在做什么），只在场景页开着时有。场景页里的回复据此用这件事的功能预设，带上两边的位置、场景规则和可用标签。

界面用 `SceneShell`（背景 + 立绘 + 顶栏 + 她的一句话 + 底部面板）：
- 背景和标题跟着地点走，例如"咖啡店 · 一起自习"；家里按房间选背景；
- 每个场景只写自己的面板（`apps/web/src/scenes/*`）。

### 节律：她每天的作息、三餐和穿着（第二阶段）

> **已实现**（本机和云端）：预设页"节律"一类和自带的 `rhythm.json`（建世界、排今天、穿着两种做法按触发条件发送）；"我的 → 节律"页；每个角色固定 / 每天变化（三项分别勾，穿着从衣柜挑或每天新编）；建世界（生成地点、身边的人、作息模板、三餐、衣柜，看过再用，地图上出现她的世界）；排今天的检查和兜底（`packages/shared/src/rhythm.ts` 的 `checkSchedule`）；用在她此刻在哪、陪伴学习的小目标、一起吃饭她吃什么、生图穿哪套、【当前环境】里她今天穿什么。数据在本机库的 `rhythm` 表；连接 Cloudflare 后，每日变化的角色会独立同步节律上下文与加密 API，由 Cron 按用户 IANA 时区凌晨 4 点生成并存入 D1，打开 PWA 后同步。各角色并发、按角色/日期幂等、失败自动重试，不受主动消息开关影响。
> **还没做**：主动消息按今天的作息和饭点来；编辑地点和底图（现在能改作息、三餐、衣柜、手头的事，地点要重建）；演示角色的世界、衣柜还写在 `locations.ts` 里，没搬进卡片文件。

- **功能和预设**：
  - API 设置里多一项「节律」，默认跟随「陪伴 · 快速」；
  - 预设页多一类"节律"，自带 `rhythm.json`。预设里有两件任务，用触发条件区分（§5.5）。
- **建世界**：导入角色时做一次（§5.4），也可以手动重建。生成她的：
  - 地点：id、名字、室内还是室外、在那里能一起做哪些事；
  - 身边的人；
  - 作息模板；
  - 三餐习惯；
  - 衣柜：每套写中文名和 NovelAI tags。
- **排今天**：每天做一次。程序填进去的输入有：
  - 角色卡；
  - 她的世界，以及不能动的固定安排（例如江屿下午的训练）；
  - 今天的日期、星期、节假日、天气、节气；
  - 最近几天的作息和穿着（避免重复）；
  - 她的衣柜；
  - 最近的约定和待跟进（例如"周六约了水族馆"），排进今天。
- **"排今天"的输出（JSON）**：
  - 作息：从 00:00 排到 24:00，一段一段写清几点到几点、在哪（地点 id）、在做什么；
  - 三餐；
  - 穿着：日常、运动、睡衣三套，有约会时再加一套约会装；每套写中文名和 tags；
  - 今天手头的事：也是陪伴学习里她的小目标；
  - 一两件小事：番外和主动消息可以用。
- **每个角色单独选**（在"我的 → 节律"里）：
  - **固定**：一直用她的作息模板、三餐习惯、衣柜里的固定搭配。这些是"建世界"生成、你改过的数据，不在代码里。
  - **每天变化**：作息、三餐、穿着三项可以分别勾选。穿着可以"从衣柜里挑着搭"（更稳），也可以"每天新编"（变化多）。
  - 新导入的角色默认固定。
- **什么时候生成**：每天凌晨 4 点（按你的时区）。接了云端就在 Worker 上生成；没接就在当天第一次打开 App 时生成。也可以手动"重新排今天"。
- **检查和兜底**：作息要覆盖整天、不重叠，地点都在她的世界里，固定的事没被挪动。不合格的部分用她的作息模板补上。
- **用在哪**：
  - 她此刻在哪、在做什么：`slotAt` 先看今天的节律；
  - 主动消息按她今天的作息和饭点来；
  - 一起吃饭时她吃的，陪伴学习时她的小目标；
  - 生图：这个场景该穿哪套就用哪套（宏 `{{char_outfit}}`），所以同一天的图衣服一致；
  - 【当前环境】里加一句她今天穿什么。
- **"我的 → 节律"页**：
  - 今天的时间线、三餐和穿着，tags 可以改；
  - 最近 7 天的记录；
  - "把今天存成模板"；
  - 编辑她的世界和模板。
- **成本**：建世界每个角色做一次；之后每个选了"每天变化"的角色，每天调用一次。

### 9.1 健身（`FitnessScene.vue`，以前的"一起运动"）

> **已实现**：照陪伴学习（§9.3）的样子分三种画面，但画面用她的立绘（节律里那套运动服），不生图。
> - **开始前（和练完）**：上下各一半。上半屏是立绘和她那边（现在的作息）；下半屏是你的安排：
>   - **按照计划**：今天的健身计划（「健康计划」按你的健康设置排的，§9.13），热身 / 动作 / 拉伸放松，每个动作点开看怎么做（大白话、少用肌肉名称）；没排过的进来时自动排（接通了的话）；
>   - **随便动动**：从你人设里能接受的健身方式挑一个（跑步、快走、骑行、登山这些是室外的），可以定个时长（不定时 / 15 / 30 / 45 / 60 分钟）；
>   - **记录**：时长一直记；心率、消耗可选；室外的再加步数和距离。选择记在本机（`ai-mobile:fitness`）。
> - **练的时候**：整屏立绘站在右边，一个半透明的圆形计时器（照计划：按时间做的那组倒计时、组间休息倒计时、按次数做的点"这组做完了"；随便动动：时长，定了时长的按目标走一圈），按住能拖到哪儿都行，拖过的位置记在本机，没拖过时放在左边、动作卡上面；下面是现在这个动作（第几组、跳过），怎么做直接展开着（照计划开练了就不用再点），再下面一排数（时长、心率、千卡、步数、公里和配速），最下面音乐（`fitMusic`，挑歌单，同 §9.4）和"跟她说一句"。暂停、结束都按时间戳算，锁屏回来对得上；练的时候屏幕保持常亮。
> - **练完**：统计；安卓自动记到的数先填好，别的手机把手表上的心率、消耗、步数、距离填进来（都可以不填）；"发给她"：运动卡片（`workout`，带 `mode`、`plan`、`heartRate`、`kcal`、`steps`、`source`）进聊天，记录也记进健康计划（按人设），她具体地评价；离开时那一段写"练了 N 分钟"。
> - **她说的话**：「陪伴 · 快速」按"健身"功能预设：开练（`fit-start`）、做完一个正式的动作（`fit-move`，提醒下一个动作最要注意的地方）、随便动动每 10 分钟和定的时长到了（`fit-cheer`）、边练边聊（`fit-chat`）、结束（`fit-end`）；右上角能让她读出来（语音合成）。
> - **连麦**（右上角，`composables/useMicLink.ts`，和共同的家一样）：手上忙着，说话她就听得到、用她的声音回你（`fit-call`，"健身"预设里的"连麦"一块）；开始前、练的时候、练完都能连，挂断也在那个按钮上。连着的时候开练、做完一个动作、练了一段时间、练完她都在麦里说（不另外念），下面打的字也走麦里那一路。语音识别没接通、麦克风用不了时改成打字，写明原因。这里右上角不放"连线 / 坐在她旁边"。
> - **进阶记录先只做安卓**（`services/workoutSensors.ts`）：心率用 Web Bluetooth 连标准蓝牙心率服务（心率带、开了"心率广播"的手表）；步数用加速度传感器（Accelerometer，没有时用 devicemotion）按波峰数；距离和配速用 GPS（watchPosition，35 米以内的点才用，原地漂移和跳点不算，暂停时不算）。消耗：知道年龄、性别、体重和平均心率时按心率算（Keytel 公式），否则按 MET × 体重 × 时长（跑步、走路按配速换 MET）；没填体重按 60 kg。iPhone、电脑不开这些。以后的安卓壳可以换成 Health Connect、前台服务（锁屏不断）。
> - **以前的设想（未实现）**：iPhone 快捷指令把健康数据 POST 到 `/v1/ingest/workout`；Keep、华为、小米的运动截图交给视觉模型识别。

- **AI 行为**：发现新的运动记录就夸或吐槽；久坐提醒；邀约"今晚一起去跑步？"；平时聊天也知道你今天练没练（"家务和健康"那一块，§5.1）。

### 9.2 一起吃饭（`MealScene.vue`）

> **已实现（照陪伴学习改版）**：外壳用 `SceneShell` 的 `bare`。开始前和吃完上下各一半（上半屏她那边：此刻在干什么、吃不吃饭、下一顿几点；下半屏：怎么吃、哪一顿、今天几顿、这周的打卡）。

> - **她说的话**：开饭 `meal-start`、按计划开始准备 `meal-prep`、准备好了 `meal-ready`、你吃的什么 `meal-food`、碰杯、边吃边聊 `meal-chat`、吃完 `meal-end`，都按"一起吃饭"功能预设里对应的块（触发条件写任务名）交给「陪伴 · 快速」，存进聊天。
> - **饭卡**：吃完发（`meal` 卡片加了 `how`、`mode`、`plan`、照片、她吃的、碰杯次数、这次画的图），离开时那一段写"吃了午饭（…）"。今天几顿、这周的打卡从聊天里的饭卡算。

- **饭搭子（默认，连线）**：各吃各的，但同时开饭。
  - 饭点前她先暗示："我准备去食堂了，你中午吃什么？"
  - 开饭时你拍一张你的饭，识图认出是什么；她也"拍"一张她那边的（她的三餐写在 `World.life`，正式版用生图画出来）。
  - 可以碰个杯，边吃边聊；吃完记一顿，她记住你的口味，也记得你没吃早饭。
- **带她去吃**：她从你家附近真实的餐厅里挑（Google 地图），吃饭时坐你对面，这家店进足迹。
- **去她那吃**：她在她的住处给你做饭，你在现实里吃你的。

> - **还没做**：摄像头；她自己休息时随口说一句（现在只换表情）；你的人设里正式加外观 tags（现在在"你这边的画面"里按人设各存一行，存在本机）。

### 9.4 哄睡（`SleepScene.vue`）
- **玩法**：四个标签——连麦（说话她就听得到、小声回你）、睡前故事（她现编）、白噪音混音（雨、炉火、海浪、风扇）、音乐（挑歌单）。
- **连麦**（`composables/useMicLink.ts`）：管线同语音通话（§11.2）：`CallListener` 说话检测 → 语音识别 → 她流式回复 → 按句合成、边合成边播；你开口时她停下，聊天里只留说出口的（`keepSpoken`）；灵敏度、停顿、能不能打断用"我的 → 语音"里通话的设置。和通话不同的地方：
  - 回复用「陪伴 · 快速」+"哄睡"功能预设（`sleep-call`），不用"语音通话"的预设；场景任务里写现在几点、灯、白噪音、在放哪首歌、连了多久；
  - 她的声音和故事、晚安共用场景里的一路（`newSpeech`：同一时间只有一段，低语的情绪、语速乘 0.88），白噪音和音乐在她说话时压低；
  - 你安静 45 秒 / 90 秒 / 3 分钟她低语一句（`sleep-whisper`），三句以后不再说，你一开口重新算；可以关；
  - 连上以后换标签不断（面板上一条"连麦中"，能闭麦、挂断）；她讲故事时你开口，识别出来不是回声才把故事暂停（防扬声器漏音误停），她再回你；连麦里她正回着时点讲故事，先停下她（只留说出口的）；
  - 屏幕常亮（Wake Lock：网页熄屏后麦克风会停），定时到点挂断；语音识别没接通、麦克风用不了时改成打字；
  - 说的话存进聊天，`cue` 是"连麦"；不发通话记录卡片（这一段已经在"哄睡"的分隔条里）。
- **白噪音**（`services/ambience.ts`）：本机用 Web Audio 合成，不联网、不用 API、没有版权问题。第一次播放时把每种声音算成一段十几秒的循环（22.05 kHz，首尾等功率交叉淡化，接缝听不出来），四个滑块调各自的增益；她说话时压低（duck）。
- **音乐**（`components/scene/PlaylistMusic.vue`，共同的家、健身也用它，各自带几个歌单）：网易云（同 §9.5 的 Worker）。播放器是 `services/musicPlayer.ts` 的 `sleepMusic`：和一起听歌各用一个实例（`createMusicPlayer`；共同的家是 `choreMusic`、健身是 `fitMusic`），播放列表分开存（`ai-mobile:sleep:music:v1`），不取歌词。
  - 歌单：助眠的几个（按"助眠 钢琴曲"这类词搜，搜到的就是歌单）、我们的歌单（一起喜欢的歌、存下的歌单 / 专辑，`services/musicLibrary.ts`，和一起听歌共用）、自己搜一个词、贴歌单 / 专辑链接（能存进我们的歌单）。没填 Worker 时是示例歌单。
  - 音量 = 你调的音量 × 压低（她说话时 0.35，下去快、回来慢）× 渐弱。iPhone 不让网页改 `<audio>` 的音量，压低和渐弱在 iPhone 上没有效果，渐弱到点照样暂停；音乐不接进 AudioContext（别的网站的音频没给跨域头时，接进去只有静音；AudioContext 被挂起时也会整个没声）。
  - 渐弱中一首放完自动接下一首时照样接着变小；你点播放、换歌单就不再变小。
- **她说的话**：连麦、低语、睡前故事、定时到点的晚安都由「陪伴 · 快速」按"哄睡"功能预设写（`sleep-call` / `sleep-whisper` / `sleep-story` / `sleep-end` 四个任务，预设里各有一块），流式生成、按句合成（`services/speech.ts`），低语用"很轻、像在耳边小声说话"的情绪、语速乘 0.88。故事第一行是《故事名》，标题不读；可以暂停（继续时从停下的那句读）。
- **定时**：到点挂断连麦，她说最后一句晚安，白噪音和音乐 45 秒渐弱到停（音乐只是暂停，列表和位置留着），她也睡着。可以熄灯。
- **叫醒**：第二天按起床时间来电。
- **平台**：
  - 安卓用前台媒体服务、精确闹钟（叫醒用 `setAlarmClock`）和全屏来电；
  - iPhone 的 PWA 锁屏后 JS 和 WebAudio 会暂停，长音频只能用单个 `<audio>` 元素，效果有限。

- **AI 行为**：按当前歌词偶尔发一句"弹幕"（20 字以内），不是每句都评；用 `[music:]` 推荐下一首；记住你的口味。
- **安全**：Netease_url 仓库里提交过一个像真的 `MUSIC_U`，应到网易云退出登录让它失效。

### 9.5.1 聊天 ＋ → 拍照 / 相册（已实现）

  - 留念：结束约会时画一张纪念照；
  - 右上角"拍一张"随时画此刻；自动画能关（和其他场景共用开关）。
- **结束**：发"约会回忆"卡片进聊天（走了几段、多少分钟、每种回法选了几次、她最后说的一句、这次画的图）；直接离开页面也算结束，卡片照发。聊天里这一段以"离开水族馆 · 约会走了 6 段，留了 2 张图"收尾。

### 9.9 一起观影（第二阶段，未实现；先只做有字幕的片）

**核心**：AI 不直接看视频。App 先把视频变成几条按"片内时间"（第几秒）排好的文字记录，AI 读的是某一段时间里记下了什么。她的每句反应也挂在一个片内时间上，播到那一秒才出现。

| 记录 | 内容 | 例子 |
|---|---|---|
| 字幕 | 谁说了什么、从第几秒到第几秒 | `00:41:08–00:41:11「伞你拿着吧。」` |
| 画面 | 这一刻画面里有什么（可以关） | `00:41:10 雨夜车站，男生把伞塞给女生，自己跑进雨里` |
| 弹幕 | 你发的、她发的 | `00:41:15 你：啊啊啊` |
| 前情提要 | 到目前为止的剧情，每 10 分钟用「陪伴 · 快速」压缩一次，300 字以内 | `两人在车站重逢……` |

**支持的看法**：

| 你怎么看 | 字幕从哪来 | 画面 | 时间从哪来 |
|---|---|---|---|
| 在 App 里放本地视频 | 外挂字幕文件（srt / vtt / ass），或视频里内封的文字字幕：MKV 用轻量解析库读，MP4 用 mp4box.js 读 | 后台第二个播放器提前截图，交给识图 | 播放器时间，精确 |
| 在电视、电影院、别的 App 里看 | 你提供的字幕文件 | 没有 | 对时：列出接下来几句字幕，听到哪句点哪句；也可以手动前后调几秒 |

- **暂不支持**：图片格式的字幕（PGS）、烧在画面里的硬字幕。没有字幕的片可以贴链接看（见下）。
- **以后再做**：转写音轨（按停顿切句再识别）、麦克风对时、电脑上共享标签页、画中画悬浮弹幕。

**贴链接看**（参考 siios 的 co-watch；`utils/videoLink.ts`）：

| 链接 | 播放器 | 时间从哪来 |
|---|---|---|
| YouTube（watch、youtu.be、shorts、live、music） | 官方嵌入播放器，`enablejsapi=1&origin=…` | 不加载 iframe_api 脚本，直接按它的 postMessage 协议：发 `listening`，收 `infoDelivery`（播放时间、状态），跳进度能认出来；十秒收不到就改成自己计时 |
| B 站（BV / av 号；分享出来的"【标题】 链接"整段也行） | 官方嵌入播放器 `player.bilibili.com`，不登录、不用自己的服务器 | 嵌入播放器不告诉网页：你在播放器里播放的同时点"开始计时"，可以 ±5 秒 |
| 视频文件（.mp4 / .webm / .m3u8 …） | App 自己的 `<video>`（m3u8 只有 Safari 能直接放） | 播放器时间，精确 |

- b23.tv 短链接在网页里展不开（没有跨域头，读不到跳转地址），提示贴带 BV 号的地址；B 站的视频信息接口同样不能从网页直接调，所以标题从分享文字里取或者你填。YouTube 的标题和频道用 oEmbed（允许跨域）。
- 认不出的网址不放进 iframe（不会把任意网页嵌进来），只当视频文件试着放。
- 有字幕文件：照上面的字幕流程批量写弹幕。没有字幕：她只知道片名、作者、你写的简介和播到哪（B 站是"大概播到…，按你点开始计时算的"），按话量用 `watch-link` 任务像发弹幕一样随口说一句（可以吐槽；认得出片名里的作品、角色时就着说；不编没出现的剧情）。多久一句：知道片长时（YouTube 播放器、视频文件）按片长分，安静 / 适中 / 话痨大约一部片 2 / 4 / 7 句，最短 10 秒一句（1 分钟的视频适中是每 12 秒一句，第一句在 7 秒左右）；不知道片长时（B 站）最多隔 3 分钟 / 90 秒 / 45 秒。没说出来时写明原因，下一句到点再试。YouTube 播放器报错（作者不允许嵌入、视频不存在）时写明原因，改成自己计时。
- 装成 App 后（安卓 Chrome）manifest 的 `share_target` 让它出现在系统分享里：从 B 站 / YouTube App 分享过来，`shareTarget.ts` 在路由创建之前把 `?share_text=…` 换成"一起观影"的地址并去掉参数。
- 选片时三种看法的顺序是：贴链接（默认选中）、在这里放视频、在别处看。

**放映厅**（手机、平板；`composables/useTheater.ts`、`components/scene/FlyingDanmaku.vue`）：
- 手机、平板上（不是电脑：有触屏、没有鼠标悬停）点"开始一起看"就进放映厅：横屏、铺满整个屏幕，她的话从画面上飘过去。"在别处看"没有画面，不进。看的时候点"全屏"能再进（电脑上也能点，进系统全屏）。
- 先让整个页面进系统全屏（`document.documentElement.requestFullscreen`，不是播放器：弹幕和按钮都在全屏里；页面能在这次点击里同步调用，播放器那时还没画出来也没关系），进去了再 `screen.orientation.lock('landscape')`（安卓的浏览器可以）。
- 进不了系统全屏（iPhone 的浏览器没有这个功能）或者被拒：放映厅本身是一个铺满屏幕、没有内边距的固定层，画面照样最大。屏幕还是竖着（锁不了横屏、开着方向锁定）时，里面的内容顺时针转 90°（框的左上角放在屏幕右上角），手机往左横过来看就是正的；系统把页面也转成横的以后就不转。
- 进出放映厅只改样式，不挪播放器的 DOM（iframe 一挪就重新加载，YouTube 会从头放）。这一页的进场动画放完不保留最后一帧（停在 `translateY(0)` 的 transform 会把里面的 `position: fixed` 困在中间 480px 那一列）。
- 播放器自己的全屏会盖住弹幕：手机上把它关掉（YouTube 加 `fs=0`，iframe 不给全屏权限，`<video>` 加 `controlslist="nofullscreen"`），全屏用放映厅。电脑上照旧。
- 弹幕：从右往左匀速飘（每秒走画面宽度的七分之一，后面的追不上前面的），一行一行排在画面上面六成里，新的一条放进最早空出来的那一行；她的带头像、底色是她的颜色，你的带一个框。系统设置了"减少动态效果"时不飘，在原地淡入淡出。电影院模式照样不出弹幕。
- 顶上一条按钮：退出全屏、片名、她在想 / 没接通、计时（B 站和读不到进度的 YouTube：-5 秒 / 开始计时 / +5 秒）、发弹幕、看完了。进来和点过以后露 4 秒，然后收成左上角一个小按钮；在打字、等你点"开始计时"时一直露着。用系统的返回手势退出全屏就是退出放映厅；YouTube 说放不了、视频放不了时自动退出，面板上写着原因。

**画面**：
- 每 8–10 秒截一张，换镜头时补一张，缩到 512 像素宽；
- 每 10 张左右打包交给识图，每张回一句描述；
- 截图只在本机做，发出去的是缩小的图片，不是视频。

**怎么对上时间轴**：
- **提前写好**：始终把接下来 5 分钟的字幕和画面准备好。她的反应每 3–5 分钟批量写一次，每条挂在一句字幕或某一秒上，播到才出现，没有延迟。
- **拖进度条、暂停、倍速**：
  - 拖进度条：没出现的反应作废，按新位置重新写；
  - 暂停：什么都不出，这时你说话她正常聊；
  - 倍速：反应挂在片内时间上，会自动跟上。
- **来晚了的反应**：晚 3 秒以上就不出了。
- **不剧透**：每批只给 3–5 分钟的内容，并要求每条只说那一刻以前的事；前情提要只写已经播过的部分；她本来就知道剧情的片，规则里写明不提后面的事。
- **你发弹幕时**：把最近 60 秒的字幕和画面一起给她，她就知道你在说哪一段。

**流程**：
- **选片**：她按天气、心情和"我们的想看清单"推荐。你说了片名后先问她看没看过，拿不准就当没看过，不编剧情。
- **开场**：关灯，选零食；连线时一起倒数，同时按播放。
- **看的时候**：
  - 她的弹幕有三档话量：安静、适中、话痨；
  - 你发弹幕，她几秒内回；
  - 暂停时可以聊两句；
  - 两边的弹幕都存进聊天，带着片内时间和那句字幕。
- **电影院模式**：放映时熄屏、不出弹幕，她把想说的话"写在票根背面"，散场后你一次翻看。
- **散场**：她打分，写一句话影评。聊天里发一张"票根"卡片：片名、日期、你们两人的评分、她的影评、2–3 条高光弹幕、这次的图。卡片也存进回忆、"我们的片单"和记忆。

**在哪看**：她世界里的电影院（例如苏晚的电影院、江屿的老影院）、她家客厅。

**生图**：用 `image-watch.json`，画入座、高光反应（一部片最多一两张）、散场。

**成本**（2 小时的片）：
- 弹幕大约调用「陪伴 · 快速」25–40 次；
- 画面打包后大约调用识图 70 次，可以关掉；
- 视频不上传、不保存，只记文件名和看到哪里。发给模型的内容在"查看提示词"里都能看到。

### 9.10 一起看书（第二阶段，未实现）

**书从哪来**：

| 来源 | 怎么读进来 |
|---|---|
| EPUB | 在本机解压，按目录分章 |
| TXT | 自动识别 UTF-8 / GBK 编码，按"第 X 章"切章 |
| PDF | 用 pdf.js，用到时才加载；带目录就按目录分章，没有就按页分 |
| 粘贴的文章 | 直接粘进来 |
| 纸质书 | 拍下这一页，交给识图读出文字：你读真书，她读同一页 |

- 书只存在本机；发给模型的只有当前这几页。

**PDF**：
- **两种看法，可以切换**：
  - 原版页面：适合教材、论文、绘本、漫画；
  - 重排成文字：手机上更好读，适合小说。
- **重排时的清理**：去掉页眉、页脚和页码；把断开的行接回去；双栏的论文按栏重排。
- **扫描版或乱码的 PDF**：有的 PDF 只有图片、没有文字层，有的字体编码有问题、读出来是乱码。这样的页先渲染成图片，交给识图读出文字，提前读前面几页。
- **加了密码的 PDF**：问你要密码。
- **批注挂在哪**：重排时挂在段落上；看原版时挂在"第几页的哪一句"上，划线画在 pdf.js 的文字层上。

**带公式的专业书**（教材、讲义、论文；参考 math-reader 的讲义和 SleepTogether 的看书）：
- **哪些页交给识图**：没有文字层的、乱码的，以及有公式的页（数学符号多，或者有很多比正文小一圈的上下标）。pdf.js 读出来的公式是乱的（分数没了分数线、上下标拆成一行一行），不拿它当正文；有公式的页留着这段文字，识图没接通时先给她看。
- **识图读成 Markdown + LaTeX**：读法写在"一起看书"预设的"识图读书页"一块里——标题加 #，列表、加粗、表格照 Markdown，公式行内 `$…$`、单独一行 `$$…$$`，编号写成 `\tag{}`；页面画成长边约 2000 像素的图，输出上限 4096。跨行的公式块、表格并成一段，不拆开。
- **提前读**：翻到一页时，识图排队读现在这页和后面两页；读好之前这一页原样显示（文字看法里也是），读完把占位换成读出来的段落，后面段落的编号、批注、读到哪跟着挪。
- **显示**：KaTeX（同 math-reader），用到公式时才加载；正文、页边批注、她说的话、聊天气泡、读书卡片都认 `$…$`、`$$…$$`、`\(…\)`、`\[…\]`。公式和紧挨着的标点不分开换行；选中公式写批注时换回公式原文。
- **她怎么批注**：预设里加一块"专业书"——批注写读到这一段的真实反应（哪一步没看懂、用了哪条定理、这个记号什么意思），公式也用 LaTeX；习题和证明不先说答案；前情提要记下讲到了哪些定义、定理和习题。模型在 JSON 里写 LaTeX 常常不转义反斜杠，解析时按 LaTeX 修回来。
- **读给你听**：公式念成中文（"从 a 到 b 的积分""偏 x 分之偏 U""e 的负 i 西塔次方""f 的绝对值"）。
- **预设跟着更新**：自带预设放进本机后是你的，App 更新只动你没改过的地方——没改过的识图说明换成新的，新加的块插进去（只插一次，你删了不再放回）。

**用位置代替时间**：
- 她的批注和反应挂在"第几章第几段"上，PDF 原版页面挂在"第几页第几句"上。
- **提前读**：你翻到第 N 页时，她已经"读"好了第 N 到 N+2 页。「陪伴 · 快速」批量给出 0–2 处划线和批注，你翻到那里才显示，不剧透。
- **前情提要**：每读完一章写一段，她能把前后串起来。

**读的时候**：
- **两种读法**：
  - 共读一本：她有自己的进度，有时比你快（"我读到下一章了，你快点"），有时比你慢（"等等我"）；
  - 各读各的：像连线自习一样，她读她世界里的书，偶尔念一句给你听。
- **互相批注**：她的批注你可以回；你划一句、写一句想法，她也会回应。都存进聊天，只引用那一句。
- **读给你听**：她用自己的声音念（语音合成），正在读的句子高亮，自动翻页；夜里越念越轻，可以直接转进哄睡。
- **你读给她听**：用语音识别听你念，她偶尔接话；念外语时她会轻轻纠正。
- **章末小读书会**：她问你一两个问题，说说她的看法；也可以猜猜接下来会怎样，下一章揭晓谁猜对了。

**生图**：用 `image-read.json`。
- 看书的她：开场时画一张；
- 书里的场景：你点"把这一段画出来"时画，画里没有她。书里的人物也建一张外观表，同一本书的插图人物保持一致。

**留下的**：
- 摘抄卡片：你划的那句，加上你们两个人的批注；
- "我们的书架"：每本书两个人的进度；
- 读完一本发一张"读完了"卡片，记进时间线和记忆，以后她会提起；
- 主动消息："今晚接着读吗？"她比你读得快时，会忍着不剧透来催你。

**在哪读**：她家的沙发和卧室、图书馆、咖啡店、江边的长椅；江屿在宿舍、江堤。

**成本**：
- 大约每 2–3 页调用一次「陪伴 · 快速」，每章再调用一次写前情提要；
- 扫描页每页多一次识图；
- "读给你听"按语音合成的字数计费。

**海龟汤**（第二阶段）

**三种玩法**：
1. **她出题，你猜**：她当主持人，知道汤底。你问是非题，她答"是 / 不是 / 无关 / 是也不是"，偶尔逗你一句。
2. **一起猜**：主持人负责判定，由程序 + 「陪伴 · 快速」担任，不扮演她。她是你的队友，也不知道汤底：会提自己的问题、冒出离谱的猜测、和你讨论。她在问中关键点、或者有了新想法时才开口。
3. **你出题，她猜**：你写汤面，汤底可写可不写（写了用来判她最后的答案），也可以从题库挑一道。她来问，你点按钮回答；最后她说出自己的推理。

**汤从哪来**：
- **题库**：`src/soups/` 里的原创题文件，第一次打开时放进题库，可以增删改（§5.5）。每道题有汤面、汤底、关键点、难度，并标明清汤还是红汤、本格还是变格。
- **现编**：先写汤底和关键点，再写汤面，再自检"只看汤面能不能问出来"。通过了才用。
- **她世界里的汤**：用她世界里的地点和人来编，只有你们俩懂。
- **尺度**：写在"一起游戏 · 海龟汤"预设里，触发条件 `soup-level:名字` 的块就是一个尺度（`SOUP_LEVEL`，和真心话大冒险一样）：自带清汤（不涉及死亡和恐怖）、红汤（可以涉及，不写血腥细节）两块。开始前按块的顺序选（上次选的记在这台设备上，`ai-mobile:soup-level`），现编（`soup-make`）和自检（`soup-check`）时只发选的那一块；题库按题的尺度（题库文件里的 `kind`）筛：列出选的尺度和排在它前面的尺度的题，对不上任何尺度的题一直列出来；现编的题记成选的尺度。`feature-game:levels` 升级本机没改过的那份。

**判得准、不矛盾**：
- 汤底和关键点存在本机，只放进主持人那次调用；界面上看不到，揭晓前不会显示。
- 每次判定都带上之前全部的问答，用低温度。判定返回 JSON：
  - 结果：是 / 不是 / 无关 / 是也不是；
  - 问中了哪些关键点；
  - 离答案近不近；
  - 一句台词。
- 她出题时，程序检查她那句话，和关键点原文重合太多就换一句。
- 一起猜时，她那边的调用里不带汤底，可以在"查看提示词"里确认。

**过程和结束**：
- **进度和提示**：显示已经问出几个关键点（例如 3 / 5）；提示分三级，由浅到深，用了算在成绩里。
- **提交答案**：你说"我知道了"时提交，判成对、半对（缺哪几点）或不对；也可以认输，直接看汤底。
- **揭晓**：显示汤底全文，配一张真相插画（`image-game.json`，画里没有她）；她说说她的看法。
- **成绩**：问了几题、用了几次提示、用了多久；一起猜时，比比谁问出的关键点多。
- **留下的**：
  - 每一问每一答都存进聊天，汤底揭晓后才存进去；
  - 最后发一张对局卡片；
  - 记忆里记下"一起解开了《X》"；
  - 之后她会主动来出题。

**预设**：`feature-game.json` 里分块写好主持、判定、提示、揭晓、出题和自检、当队友这几种规则，按这次要做的事只发对应的那一块。

**在哪玩**：她家客厅、咖啡店；江屿在宿舍、夜宵摊。

**成本**：一道题一般问 20–40 次，每次调用一次「陪伴 · 快速」；一起猜时，她说的话另算。现编一道题调用 2 次。

> - **说话**：打字走主对话 + "心跳"功能预设（`scene:heart`，自带"心跳 · 文字"：开场 `heart-open`、打字聊 `heart-chat`）；连麦走 `useMicLink` + 「陪伴 · 快速」+ 新的用途"心跳 · 语音"（`heart-voice`，自带"心跳 · 语音"：连麦回你 `heart-call`、你安静一会儿她轻声说一句 `heart-murmur`）。`useMicLink` 加了 `use`、`flags`、`allowedTags`、`onTurnStart`、`onParsed`、`onReply`；`generate` 加了 `flags`（额外的预设触发条件）和 `onParsed`（流式时、写完时给解析好的正文和标签位置）。说的话都存进聊天，离开时那一段写"心跳 N 分钟 · 最快 …"。没接通时不出演示台词。
> - **背景**：用途 `image:heart`，时刻 `open`（开场）、`now`（这一刻）。进来时用今天在同一个地方画过的竖图，没有就画开场；之后她每说几句（默认 6，能改成 4 / 8 / 不自动）画一张这一刻，魔杖马上画。`SceneDrawRequest.lockOutfit = false`：衣服按对话写。自带三个生图预设：氛围（默认）、第一视角、亲密（到了亲密的时候加 nsfw 照实画，负面词固定写 loli, child, underage）；在场景的设置里换，也能跟随配图。
> - **Intiface Central**（`services/intiface.ts`）：自己写的 Buttplug v3 客户端（JSON 走 WebSocket）：`RequestServerInfo`（MessageVersion 3）、`RequestDeviceList` / `DeviceAdded` / `DeviceRemoved`、`StartScanning`（15 秒后停）、`ScalarCmd`（Vibrate / Oscillate / Rotate / Constrict / Inflate / Position）、`LinearCmd`、`RotateCmd`、`StopDeviceCmd` / `StopAllDevices`、`SensorReadCmd`（电量）、服务器要求时按 `MaxPingTime` 的一半发 `Ping`。地址写 `127.0.0.1:12345`、`ws://…`、`wss://…`；页面是 https 时浏览器只让连回环地址和 wss（混合内容），连之前先判断，写明怎么办（同一台设备上开 Intiface，或者给它套 https）；连不上、断开都写原因。连接留着，再进心跳不用重连（连上过就自动连），点"断开"才断。
> - **指令**（`packages/shared/src/device.ts`）：键沿用插件——`VIBRATE` / `OSCILLATE` / `ROTATE` / `CONSTRICT` / `INFLATE`（0–100、每个马达的数组、`{pattern, interval, loop}`，pattern 的一档也可以是数组；旋转可加 `clockwise`）、`LINEAR` / `LINEAR_SPEED` / `LINEAR_PATTERN`（伸缩）、`STOP`。读法宽松（全角标点、单引号、没加引号的键、注释、分号、同一行接着写下一个键）。两种来源：
>   - **单独生成**（默认）：新的预设分类"控制指令"（`device`，用途 `device`，自带"控制指令 · 心跳"）和新的 AI 功能「控制指令」（`AgentRole` 加 `device`，默认跟随「陪伴 · 快速」）。她每说完一句，程序填充块（`TASK_MARKERS.device`：连着的玩具和能写的键、强度上限和最快速度、玩具现在在做什么、最近的对话、她这一句）交给预设，输出 `{"steps": [{"at": "她原话里的几个字", "do": {...}}]}`（`parseDeviceSteps`），`placeSteps` 按 at 找位置（不看标点空格、按顺序往后找、找不到用前一半、再找不到夹在前后两步中间）；
>   - **她自己写**：心跳的功能预设里"她自己写指令"那一块（触发条件 `device-inline`，只在连着玩具、选了这一种时发送），她在回复里写 `<device>`，`parseControlTags` 给出位置。
> - **执行**（`services/toyPlayer.ts`）：`ReplyTimeline` 一句话一条时间线：打字时按"读多快"（默认每秒 9 个字）往前读、不超过已经写出来的字；连麦时跟着念到第几句，句子里按每字 210 毫秒走、到句末等下一句；来晚了一下子到的几条合成一条（`mergeCommands`，后面的盖过前面的、停下清掉之前的）。她开始说下一句、你打断、离开时，没执行的不再执行，晚到的单独生成也作废。`ToyPlayer` 每一种各放一段：新指令只换掉它写了的那几种；变速按 pattern / interval 走，loop 放完归零；伸缩在两个位置之间来回（幅度按设置的范围映射，不快于"一下最快"）；强度不超过上限；和上一次发的一样不再发；每一档至少 120 毫秒。玩具做不了的键去掉（`fitCommand`）。没连玩具时可以"在心跳上试"：只算强度给界面看。
> - **安全**（`stores/toys.ts`，设置存本机 `ai-mobile:toys`）：每一种的强度上限、伸缩最快和范围；"停"发 `StopAllDevices`，之后她的指令先不执行、也不再调「控制指令」，点继续才接着来；多久没有新指令就停（默认 10 分钟，能改成不停）；切到后台、锁屏时停（默认开）；离开心跳、断开、连接断了都停。

## 10. 立绘与 NovelAI

### 10.1 立绘套装
- **组成**：服装 × 姿势 × 表情；按 `{服装}_{姿势}_{表情}.webp` 批量导入。
- **缺图回退**（`resolveSprite`）：同服装同姿势 neutral → 同服装默认姿势 neutral → 默认服装 neutral。
- **默认服装**：场景决定（运动服、睡衣、约会装……）。
- **兼容 ST 表情文件夹**：ST 的 28 个分类标签映射到本 App 的表情：

| 本 App 表情 | ST 标签 |
|---|---|
| 平静 | neutral |
| 微笑 | admiration、approval、caring、gratitude、optimism、relief、pride |
| 大笑 | joy、amusement、excitement |
| 脸红 | love、desire |
| 害羞 | embarrassment、nervousness |
| 嘟嘴 | disgust、annoyance |
| 惊讶 | surprise、realization、confusion、curiosity、fear |
| 难过 | sadness、grief、disappointment、remorse |
| 生气 | anger、disapproval |

- **提示词**：只把有图的表情写进提示词。
- **切换**：表情交叉淡化 260ms；立绘预加载，用 `img.decode()` 避免闪烁。

### 10.2 NovelAI
- **调用**：Worker 代理 `POST https://image.novelai.net/ai/generate-image`。
  - 模型 `nai-diffusion-4-5-full`；
  - V4 起用 `v4_prompt`（多人时用 `char_captions`）；
  - 返回 zip，Worker 解出 PNG 存 R2。
- **提示词**：外观基础 tags + 负面 tags 来自角色卡，生图提示词智能体补动作 / 服装 / 场景。
- **Opus 免费无限出图，必须同时满足四条**（生成按钮上显示 0 Anlas 就是免费）：
  1. **尺寸在 Normal 档以内**（总像素不超过 1024×1024）：
     - Normal 档：竖图 832×1216、横图 1216×832、方图 1024×1024；
     - Small 档（512×768、768×512、640×640）也免费；
  2. **步数不超过 28**；
  3. **一次只出 1 张**；
  4. **不用图生图**。
- **模型**：选 V4.5 或更早的。V5 现在有用量上限，用完要等它慢慢恢复，从空到满大约一周。
- **App 怎么守住**：
  - 每次自动出图前，检查这四条和模型，有一条不满足就不自动出；
  - 出完读一次订阅余额，确认没有扣点。
- 现在代码里的尺寸（`packages/ai/src/image/presets.ts`：竖 832×1216、横 1216×832）就在免费范围内。
- **一致性**：见 §10.4。
- **相册**：保存提示词、种子、模型，可以"用同样参数重画"。

### 10.3 生图按场景分预设、按角色 id 填长相（第二阶段）

> **已实现**：预设页"生图"的"用在哪"按 `SCENES` 每个场景一项，可以选任何生图预设或"跟随配图"；自带 `image-study.json`（偷拍、奖励、你这边，以前的入座，`IMAGE_MOMENTS`）。宏 `{{char_appearance}}` `{{char_outfit}}` `{{user_appearance}}`；程序按角色 id 把人数 tags、长相（同人是角色 tag + 作品 tag）、节律里这个场景该穿的那套加在最前面。陪伴学习（§9.3）：专注开始时画一张（今天同一个地方、同一身衣服、同一种画幅画过的直接用图库里的）、每个番茄中间自动偷拍一张、"看她一眼"马上画一张、学完画奖励图，都放进学习卡片；画幅由程序按画面定（`ImagePromptInput.size`：一起专注竖图，各自专注上半屏方图或横图），各自专注的下半屏可以按你的人设画（`IllustrateRequest.subject`）；右上角能关自动画，NovelAI 只在不花点的设置下自动画（步数 ≤ 28、不用 V5）。
> 约会：自带 `image-date.json`（到达、关键时刻、留念，§9.6）。
> **还没做**：观影、看书、海龟汤的场景生图预设和时刻（现在跟随配图）；预设里的出图参数（画风、步数）。

**同一个预设，不同角色**：
- 预设里不存任何角色的长相。画谁，程序就按她的 id 取她的外观、这个场景该穿的那套衣服、vibe，填进预设。
- 预设里可以用宏 `{{char_appearance}}`、`{{char_outfit}}`、`{{user_appearance}}`（§5.2），和 `{{char}}`、`{{user}}` 一样按这次画的角色替换。你的人设里要加一栏外观 tags。
- 所以角色 A 和 B 用同一个"一起观影"生图预设，画出来是各自的脸、各自今天的衣服。

**每个场景一个生图预设**：
- 预设页"生图"这一类的"用在哪"，从现在的一项（配图）变成每个场景一项，按 `SCENES` 自动生成。每项可以选任何生图预设，或者"跟随配图"。
- 自带这些预设文件，都放在 `src/presets/`：

| 预设文件 | 用在 | 时刻（块的触发条件） | 这个场景的规则 |
|---|---|---|---|
| `image.json`（现有） | 聊天配图 | 画一个场景 / 全身像 / 脸部特写 / 只画背景 | 不变 |
| `image-study.json` | 陪伴学习 | 偷拍、奖励、你这边（各自专注的下半屏，画的是你）；入座（以前用） | 图书馆或书桌；台灯和窗外的天气按当时；画幅由程序定（一起专注竖图，各自专注方图或横图） |
| `image-watch.json` | 一起观影 | 入座、高光反应、散场 | 暗光，脸被屏幕照亮；屏幕上不画片子里的具体画面 |
| `image-read.json` | 一起看书 | 看书的她、书里的场景 | 暖光；画书里的场景时不画她，按书中人物外观表画 |
| `image-game.json` | 海龟汤 | 想题、揭晓、真相插画 | 画真相插画时不画她，红汤也只用暗示 |
| `image-date.json` | 约会 | 到达、关键时刻、留念 | 按地点和天气画；可以两人同框 |
| `image-meal.json` | 一起吃饭 | 对面（共同吃饭的整屏背景）、她那边（各吃各的上半屏）、碰杯 | 食堂、餐厅或她自己的桌前；桌上的饭按她这顿吃的写；画幅由程序定（共同吃饭竖图，各吃各的方图或横图） |

- 运动、哄睡、听歌、戳戳乐先跟随配图，以后要画时再加。
- **一个场景生图预设里有什么**：
  - 任务和规则：这个场景的构图、光线、道具；
  - 每个时刻一块：触发条件写时刻名，写明画不画她、竖图横图还是方图（都在 Normal 档以内）、这个时刻固定加的 tags；
  - 输出格式；
  - 程序填充块：外观、穿着、地点和时间天气、最近的对话、要画的画面、画面里的其他人物（书里的人、汤里的人）；
  - 出图参数（可选）：画风前后缀、负面词、尺寸、步数、采样器。不填就用 API 设置里的生图风格。尺寸只能选 Normal 档或 Small 档，步数不超过 28（§10.2 的四条）。
- **分工**：长相跟着角色走，预设只管画什么、怎么构图、什么光线。自带的几个预设用同一套画风，只改构图和光线，免得影响她像不像。
- **流程**：
  1. 场景说画哪个时刻，加一句中文画面描述；
  2. 生图提示词按这个场景的预设写 tags；
  3. 程序按 id 补上外观、穿着和 vibe；
  4. 出图。

  图还没好时照常显示立绘，好了再淡入；活动结束的卡片会带上这次的图。

## 11. 语音

### 11.1 接口（按角色配置音色）
- **TTS**：
  - OpenAI 兼容 `/audio/speech`（硅基流动 CosyVoice、各家中转）、MiniMax、Fish Audio、自建 GPT-SoVITS；
  - Edge TTS 可选，经 Worker；
  - 安卓系统 TTS 兜底。
  - 处理：表情映射成情绪参数；朗读前去掉（动作描写）和 emoji；按文本哈希缓存音频。
  - CosyVoice 的情绪指令（正文前加"你能用害羞的语气说吗？<|endofprompt|>"，硅基流动文档的写法）默认关：有的服务和上传的音色不认这个写法，会把指令原样念出来。API 设置 → 语音合成、"我的 → 语音"里可以打开。MiniMax 的 emotion、gpt-4o-mini-tts 的 instructions 是单独的参数，不会被念出来，照常用。
- **STT**：OpenAI 兼容 `/audio/transcriptions`（Whisper、SenseVoice），安卓系统识别兜底。

### 11.2 通话管线与延迟预算

| 步骤 | 目标 |
|---|---|
| 检测你说完（VAD；现在是能量 + 自适应底噪，以后可以换 silero / `@ricky0123/vad-web`） | 0.3–0.5 秒 |
| 语音识别（短句） | 0.3–0.6 秒 |
| 主对话首 token（用"通话 · 短句"预设） | 0.4–1.0 秒 |
| 凑够第一句 | 0.2–0.4 秒 |
| TTS 首段 | 0.3–0.6 秒 |
| **首句出声** | **约 2 秒** |

- **实现**（`composables/useVoiceCall.ts`、`services/listener.ts`、`services/speech.ts`；哄睡的连麦用同一套听和说，见 §9.4）：
  - 听：麦克风开回声消除、降噪、自动增益，AudioWorklet（老浏览器退回 ScriptProcessor）把 PCM 交给主线程；安静时学底噪，比底噪响一定倍数并持续 120 毫秒算开口，停顿（默认 0.8 秒，可调）算说完；带开口前 0.4 秒，本机降到 16 kHz 写成 WAV 交给"语音识别"。也可以按住说话或打字。
  - 说：主对话用"语音通话"这个用途选的预设（默认"通话 · 短句"），只执行表情标签；流式正文按句切（句末标点后面又来了字才切），下一句在这一句播放时就开始合成。
  - 播：语音只走共享的 `<audio>`，不接进 AudioContext（被挂起或 iPhone 开着静音键时会整个没声），口型和声波用解码后算好的响度包络。
  - 防回声：她说话时门槛提高、要持续 280 毫秒才算你开口；识别出来的和她刚说的大半重合就当回声丢掉。
  - 没接通：哪一步没接通界面就写哪一步（语音识别 → 改打字，语音合成 → 只有字幕，主对话 → 她不说话），不出演示台词。
- **打断**：她说话时检测到你开口，立刻停止播放、取消生成，聊天里只留已经说出口的句子（`keepSpoken`）。
- **字幕**：边播边出。
- **通话记录**：生成卡片进聊天，并参与记忆总结。
- **平台差异**：
  - iPhone：锁屏后中断，只能前台通话；
  - 安卓：前台服务（麦克风 + 媒体播放）保证锁屏不断。

### 12.2 D1 建表草案

```sql
-- 所有可同步记录放一张表：同步逻辑统一；按 kind + parent 建索引，满足 Cron 查询
CREATE TABLE records (
  kind       TEXT NOT NULL,          -- character / chat / message / memory / lorebook / preset / activity …
  id         TEXT NOT NULL,
  parent_id  TEXT,                   -- message→chatId，memory→characterId …
  seq        INTEGER NOT NULL,       -- 服务器分配，全局递增
  updated_at INTEGER NOT NULL,       -- 客户端时间，只用于同一条记录并发编辑时的"后写者赢"
  deleted    INTEGER NOT NULL DEFAULT 0,
  device_id  TEXT,
  data       TEXT NOT NULL,          -- JSON，永远不含 Key
  PRIMARY KEY (kind, id)
);
CREATE UNIQUE INDEX idx_records_seq ON records(seq);
CREATE INDEX idx_records_parent ON records(kind, parent_id, updated_at);

CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);           -- next_seq、schema_version
CREATE TABLE blobs (hash TEXT PRIMARY KEY, mime TEXT, size INTEGER, created_at INTEGER);
CREATE TABLE devices (id TEXT PRIMARY KEY, name TEXT, platform TEXT, token_hash TEXT, last_seen INTEGER, cursor INTEGER);
CREATE TABLE push_subscriptions (id TEXT PRIMARY KEY, device_id TEXT, kind TEXT, endpoint TEXT, keys TEXT, enabled INTEGER, last_ok_at INTEGER);
CREATE TABLE secrets (connection_id TEXT PRIMARY KEY, ciphertext TEXT NOT NULL, iv TEXT NOT NULL, updated_at INTEGER); -- AES-GCM，KEK 在 Worker secret
CREATE TABLE touchpoints (id TEXT PRIMARY KEY, character_id TEXT, rule_id TEXT, due_at INTEGER, status TEXT, data TEXT);
CREATE INDEX idx_tp_due ON touchpoints(status, due_at);
CREATE TABLE usage (date TEXT, agent TEXT, tokens INTEGER, PRIMARY KEY (date, agent)); -- 后台智能体每日 token 预算
```

### 12.3 同步协议
- **拉取**：`GET /v1/sync/pull?since=<seq>&limit=500` → `{ records, next, more }`。第一次同步分页拉。
- **推送**：`POST /v1/sync/push`，body 为 `{ deviceId, records: [{ kind, id, parentId, updatedAt, deleted, data }] }`。
  - 服务器在一个 D1 batch 里分配 seq 并写入；
  - 同一条记录被别的设备改得更晚时，保留更新的那份并返回冲突。
- **客户端发件箱**（Dexie）：
  - 失败后指数退避重试（沿用 math-reader 的锁、去重、退避）；
  - 触发时机：启动、回到前台、改动后防抖、每 15 分钟、下拉刷新；
  - 生成回复期间暂停。
- **保护**：
  - 一次删除大量记录需要二次确认；
  - 云端非空时不被本机空数据覆盖；
  - 每天把全量 ndjson 备份到 R2，保留 7 天；
  - 可导出 ZIP。
- **Key 不进同步数据**：
  - 可选"同步密码"：本机派生密钥加密后放进一条 `kind = keyring` 的记录，Worker 只见密文；
  - 交给 Worker 的 Key 走 `/v1/secrets`，只写不读。

## 16. 安全与隐私

- **Key 分三档，按连接设置**：
  - 只在本机（默认，永不进同步数据）；
  - 交给 Worker（AES-GCM 加密存 D1，KEK 在 Worker secret；只写不读，只有后台智能体和"经 Worker 转发"会用）；
  - 无需 Key。
- **设备间同步 Key**（可选）：用你自己的同步密码在本机派生密钥加密，Worker 只存密文。
- **登录**：单用户密码换设备令牌，D1 只存令牌哈希；登录失败按 IP 限流；新设备扫码配对。
- **转发**：只允许"连接"里配置过的主机，不做开放代理。原 Netease_url Worker 是 `ACAO: *` 且无鉴权，并入中枢后加鉴权。
- **网易云 cookie**：只存 Worker secret。
- **通知**：锁屏可以只显示名字或完全隐藏。
- **家的地址和位置**：
  - 家的地址只存在你的设备，随同步只进你自己的 Worker；
  - 不写进代码仓库，也不发给对话模型，模型只知道"你在家 / 出门了 / 离家多远"；
  - 打开地图时，坐标会发给 Google，这是用 Google 地图绕不开的；
  - 定位只在打开 App 时取一次，不在后台定位。
- **数据**：全部在你自己的 Cloudflare 账号里，随时导出（ZIP / SillyTavern 格式）。不接任何第三方统计。
- **心跳的玩具**：浏览器只连你填的 Intiface Central 地址（通常是本机），指令只在这台设备上发；强度上限、"停"、没有新指令时自动停、切到后台时停、离开时停都在本机执行，不依赖模型听不听话（§9.14）。
